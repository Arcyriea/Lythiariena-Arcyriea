Redemptis-Tiariea — Asset Pipeline Migration Plan (Revised)

Status: planning only. No files modified. Corrections from the architectural review are integrated below; confirmed repository facts are restated and any earlier error is explicitly retracted.

Corrections to the original audit

Correction 1 — source-to-runtime path model (was conflated).
The original audit collapsed three distinct concerns into one "source path":
- Physical source path — where the bytes live (private/... or public/...).
- Logical asset path / identity — the stable relative path used to derive texture keys and aliases (e.g. Ships/human-dreadnought.svg).
- Runtime loading location — the URL Phaser actually fetches (/assets/..., /minimap/..., /favicon.svg).

The private tree must preserve the logical structure of the existing public tree, not necessarily mirror the public/assets/ container name. Three separate roots exist and must not be merged:

Retraction: the earlier recommendation to create private/assets/minimap/ and emit /assets/minimap/ URLs is wrong. It would duplicate-load the minimap icons (they are already loaded by MiniMap.ts via /minimap/) and invent URLs that nothing consumes. The minimap root must map to a logical minimap/ identity whose runtime URL stays /minimap/....

Correction 2 — first migration category (minimap rejected).
The minimap category is not a valid first test: it is not managed by publicSvgManifest at all, has no legacy aliases, and is loaded through a hardcoded table. Migrating it exercises none of the manifest pipeline (key normalization, collision resolution, alias emission) that the rest of the migration depends on.

Recommended first category: Ships/ (10 SVGs). Rationale:
- Fully owned by publicSvgManifest — exercises key normalization, URL encoding (spaces, #), and the LEGACY_ALIASES map (human-dreadnought, alien-interceptor).
- Directly referenced at runtime by main.ts debug blueprints (public-ships-human-frigate, public-ships-alien-interceptor) and by ShipBlueprint visual sprites — so texture-key preservation is verifiable end-to-end.
- Self-contained: no cross-category dependencies, no planet PNG coupling.
- Low risk: 10 files, all PROJECT_OWNED, no third-party copyright.

Correction 3 — clean-clone manifest architecture (critical).
Confirmed: src/generated/publicSvgManifest.ts is generated at runtime by predev/prebuild, not committed. Once private/ is absent in a clean clone, the generator has no source to read and cannot recreate the manifest from the original artwork.

This is the single biggest architectural gap. The fix is an authoritative bundle index that is committed and source-independent:

- A committed public/assets/asset-manifest.json (or equivalent) that is the authoritative record of every asset's stable ID, texture key, aliases, logical path, MIME type, and the SHA-256 fingerprint of its compiled content.
- The .bin bundles contain the compiled asset bytes keyed by the same stable IDs.
- Development mode: the generator still walks private/ and produces the manifest + bundles, but it never becomes the sole source of truth — it must reconcile against the committed index.
- Source-unavailable mode: the runtime reads the committed index + committed .bin bundles. No generation step runs. If a bundle referenced by the index is missing or its fingerprint fails, fail clearly.

The bundle metadata must preserve: asset ID, texture key, aliases, logical path, format version, and per-asset fingerprint. This is what lets the game start from committed .bin alone.

Correction 4 — copyright / SVG validation responsibilities (two errors in the original).
Re-inspected add-svg-copyright.mjs:

1. analyzeSvgMetadata() initializes isMalformed: false and never assigns it inside the parser callbacks — the field is dead. It is structurally incapable of reporting a malformed file.
2. The parser.onerror handler calls parser.resume() and swallows errors, so even a genuinely broken SVG passes "analysis" unflagged.
3. Its isValidXml() (used only for insert-validation, not for the dry-run report) is a real strict check via saxes, but it is not applied to every file during a dry run.

Therefore the original audit's claim that the copyright script provides strict XML validation is incorrect. Corrected responsibilities:

- add-svg-copyright.mjs keeps its copyright/ownership role: insert, verify, and preserve RDF metadata and ownership classifications. It should be made honest about isMalformed (set it from isValidXml before parsing, or drop the field).
- A separate strict validation responsibility belongs to the packaging pipeline: every source SVG must pass strict saxes XML parsing before bundling. Reuse the existing saxes dependency; do not rely on the copyright script's analysis path.
- Ownership classifications (36 entries, all PROJECT_OWNED, fallback UNKNOWN) and existing copyright metadata are preserved untouched.

Confirmed count correction: scripts/svg-ownership.json contains 36 entries (31 assets/ + 1 favicon.svg + 1 icons.svg + 3 minimap/), not 44. The generated manifest contains 31 entries.

Correction 5 — Phaser runtime interface (async preload).
Inspected node_modules/phaser/dist/phaser.esm.js: Scene.preload() is not async-awaited by the engine. Phaser fires this.load.on('complete', listener) once the loader finishes, and create() runs after. There is no Promise-based preload contract.

Consequence for the design: bundle contents cannot be prepared inside an async preload(). Correct approach:
- Register textures in preload() via this.load.svg(key, dataUrl) where the bundle has already been decoded to data-URLs/Blobs before preload runs — i.e. decode during an explicit bootstrap stage (a dedicated BootstrapScene or a pre-Phaser init step) that runs before BootScene.
- Alternatively, a custom LoaderFile type that reads from an in-memory buffer instead of a URL.
- The existing texture-key interface (public-ships-human-frigate, minimap-fighter, etc.) must be preserved exactly; only the source of the bytes changes.

Correction 6 — Vite configuration.
Agreed: do not add vite.config.js merely to exclude private/. Vite's default public dir is public/; private/ is a sibling directory and is not served or bundled by Vite by default, so no config is needed to keep it out of the build. The correct safeguard is an explicit production-output verification step (Phase 10) that scans the built dist/ for uncompiled SVG source (raw <svg tags, copyright metadata blocks) and fails the build if any artwork leaked.

Encryption, RTAB/AES-256-GCM, signed manifests, community .rtmod packages, and Shipmaker shared-provider infrastructure are explicitly out of scope for this initial implementation.

Recommended first implementation task

Phase 1 + Phase 2, category Ships/ only — establish the multi-root source mapping and migrate the 10 ship SVGs.

1. Define the logical-to-physical mapping as a single shared constant (e.g. in a new scripts/asset-roots.mjs):
   - assets/Ships/... → private/assets/Ships/... (logical assets/ root)
   - assets/Components/..., assets/Turrets-Platforms/... → same pattern
   - minimap/... → private/assets/minimap/... (logical minimap/ root, runtime URL /minimap/... unchanged)
   - favicon.svg, icons.svg → private/root/...
2. Copy public/assets/Ships/*.svg → private/assets/Ships/ (preserving paths and embedded copyright metadata).
3. Parameterize generate-public-svg-manifest.mjs and add-svg-copyright.mjs on the shared root constant (both already accept a root arg; wire the constant through). Update svg-ownership.json keys for the 10 ship files to private/....
4. Verify: manifest keys/aliases identical to current; copyright dry-run reports 0 malformed (with the isMalformed fix); git status shows private/ ignored; per-file hashes match.
5. Leave public/assets/Ships/*.svg in place — runtime untouched, texture keys preserved.

This is the smallest slice that exercises the manifest pipeline end-to-end (the thing the minimap category cannot), establishes the multi-root mapping before any bundling exists, and preserves every runtime URL, texture key, and legacy alias.

Test and verification criteria

- Phase 1: node scripts/generate-public-svg-manifest.mjs from private/ produces byte-identical keys/aliases to the current public/ run; node scripts/add-svg-copyright.mjs --dry-run reports 0 malformed after the isMalformed fix; git check-ignore private/assets/Ships/human-dreadnought.svg succeeds; SHA-256 of each private/ file equals its public/ counterpart.
- Phase 2: node scripts/package-assets.mjs produces ships.bin + asset-manifest.json; re-run is a no-op (fingerprints unchanged); removing one source SVG fails with a clear "missing asset" error; corrupting a .bin is detected by fingerprint mismatch on validate; existing npm test unchanged (120/2 baseline).
- Phase 3–4: strict saxes parse rejects a malformed SVG before bundling; fingerprint record is present for every asset and matches on re-validation.
- Phase 5: editing one private/assets/Ships/*.svg rebuilds only ships.bin within ~2s; no partial bundle observable (temp-file + rename).
- Phase 7: npm run predev succeeds with private/ present (generates) and with private/ absent (validates committed bundles only, fails clearly if a bundle is missing).
- Phase 8: game boots from committed .bin alone; public-svg-manifest.test.ts still passes; new test asserts provider resolves the same keys including legacy aliases central-hull, human-dreadnought, alien-interceptor.
- Phase 9: per-category git rm public/assets/<cat>/*.svg after verification; build still works from .bin.
- Phase 10: simulated clean clone runs npm run dev/build from committed bundles only; dist/ scan finds zero uncompiled SVG source; git check-ignore private/ succeeds.

Explicit clean-clone confirmation

Yes — a clean clone can run the game without private source artwork, provided Phase 3 and Phase 7 are completed as specified:

- The committed asset-manifest.json is authoritative and source-independent.
- The committed .bin bundles contain all compiled asset bytes.
- predev/prebuild run in validate-only mode when private/ is absent: they check bundle presence, format version, manifest entries, and fingerprints, and fail clearly if any are missing or invalid — they do not attempt generation.
- The runtime loads through BundleAssetProvider, which reads the committed index and bundles only.

Until those phases land, the clean-clone guarantee does not hold: today a clean clone regenerates the manifest from public/ SVGs, and removing those sources breaks predev.
