Folder naming and discovery
The packager will enumerate immediate category directories under private/assets/, recurse within each, and reconcile every supported file to exactly one registry entry. Empty category directories emit no bundle; registered-but-missing files fail. A new category with registered supported assets generates its own bundle without a new category-specific packager rule.

Normalization recommendation: permit ASCII category names made of alphanumeric groups separated by spaces, underscores, or hyphens; lowercase and normalize separator runs to hyphens. Reject non-ASCII and unsafe names rather than transliterating or renaming them. Detect normalized-name and case-insensitive path collisions before output changes. Never append automatic suffixes or rename source folders.

Unregistered .svg or .png: fail explicitly; do not invent IDs or metadata.
Unsupported file extension inside a category: fail with the path rather than silently ignore it.
Wrong extension/content-type pairing or malformed source: fail before publication.
Symlinks/reparse points, traversal, duplicate paths, and case collisions: reject.
JSON and unknown content types: remain unsupported in this phase.
PNG resource and validation policy
The largest observed PNG is 2,671,838 bytes; all five are 2000×1000. Proposed conservative limits for future files:

Maximum dimensions: 4096 × 4096.
Maximum decoded pixel bound per image: 64 MiB (4096 × 4096 × 4 bytes).
Maximum aggregate decoded pixel bound per packaging/validation run: 256 MiB.
Maximum compressed file size per PNG: 8 MiB.
Maximum aggregate compressed PNG bytes per run: 32 MiB.
These limits leave headroom over the observed 2K×1K images while bounding decompression work. Validation should use a bounded streaming/incremental inflater and scanline accounting, not allocate unbounded decoded images. It must validate PNG signature, IHDR fields and dimensions, chunk ranges/order/CRCs, required chunks, IDAT zlib data and scanline structure, IEND termination, and absence of trailing bytes. Reject unknown critical chunks. Package the original PNG bytes verbatim; do not decode/re-encode or add compression.

SVG validation retains the existing UTF-8 XML well-formedness and SVG-root checks, with original payload bytes preserved.

RTAB stays v1.0 / 0x0100: existing 64-byte outer header, 28-byte index header, 72-byte records, SHA-256 semantics, and compression = NONE. Use content type 0 for SVG and 1 for PNG. JSON (2) and Unknown (3) are not packageable.

Publication, rollback, and stale bundle ownership
Generate and validate the complete output set before publishing. Use same-volume temporary files adjacent to outputs, publish bundles and schema before the manifest, and publish the manifest last as commit marker. Roll back handled failures to the prior valid files.

Overwrite or remove only files whose ownership is established by a valid prior generated manifest with confined public/assets/ paths. Never wildcard-delete bundles or temporary files. Preserve the existing tracked public/assets/Ships/ships.bin until the new four-bundle set validates and publishes. Then retire that specific stale manifest-owned bundle. On failure, leave it and prior outputs untouched.

Multiple renames are not crash-atomic. If the process terminates mid-publication, the next full preparation must inspect manifest, fingerprints, and known transaction artifacts, then either safely restore a clearly identified backup or stop and report ambiguity. It must not automatically delete ambiguous orphaned backups or temporary files.

No stage changes the Git index. After successful publication, new root-level bundles will be untracked until the user decides to stage them; removing the old nested bundle is a worktree deletion only. Existing tracked manifest/schema updates will appear as worktree modifications.

It will cover SVG/PNG changes, registry edits, directory/category changes, debounce, single-flight serialization, event coalescing, safe category-only rebuilds, full reconciliation for ambiguous or structural changes, source stability, failure preservation, and clean shutdown.
