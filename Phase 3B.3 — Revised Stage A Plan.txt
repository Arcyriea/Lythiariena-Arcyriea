Folders determine membership.

Reject unsafe paths, traversal, case-insensitive collisions, normalized category-name collisions, symbolic links, junctions/reparse points, and non-regular entries. Use lstat and Windows reparse-point checks rather than relying on stat, which follows links.

Files directly under private/assets/, outside a category directory, must fail explicitly; they may not be silently ignored.

Normalization recommendation: permit ASCII category names with alphanumeric groups separated by spaces, _, or -; lowercase and normalize separator runs to hyphens. Reject non-ASCII and unsafe names; never transliterate, rename folders, or append suffixes.

Empty category directories emit no bundle.
A new category emits a bundle only if it contains registered supported assets.
Missing registered sources and unregistered SVG/PNG files fail.
Any unsupported extension within a category fails with its path; it is not silently ignored.
Wrong extension/content-type pairings and malformed files fail before publication.
JSON and unknown types remain unsupported.
4. RTAB v1.0 and PNG validation profile
Keep RTAB at 0x0100: existing 64-byte outer header, 28-byte index header, 72-byte records, SHA-256 semantics, and compression = NONE. Store original SVG/PNG bytes unchanged. SVG record content type is 0; PNG is 1; JSON (2) and Unknown (3) remain unsupported.

For each record, require its content type to equal both the corresponding manifest asset and registry entry. The content type is not merely a validator selector. Tests must cover SVG-record/PNG-metadata and PNG-record/SVG-metadata mismatches.

PNG profile
The five inspected PNGs are all RGBA8, non-interlaced. Stage A should accept only:

Bit depth 8, color type 6 (RGBA)
Compression method 0, filter method 0
Interlace method 0
Reject unsupported IHDR profiles, including Adam7, before decompression. Future support for other color types, bit depths, or interlace would require a separately defined and tested calculation profile.

Proposed limits:

Dimensions: maximum 4096×4096.
Compressed PNG size: maximum 8 MiB per file and 32 MiB aggregate.
Decoded pixel bytes: maximum 64 MiB per image and 256 MiB aggregate.
Inflated scanline data: calculate from IHDR as height × (1 + width × 4) for supported RGBA8 non-interlaced files, including one filter byte per row; cap per image at 64 MiB + 4096 bytes and aggregate at 257 MiB.
Use checked integer arithmetic before decompression. Stream through a bounded inflater and stop if output exceeds the calculated size or configured aggregate. Do not allocate an unbounded decoded buffer. Require exactly the expected inflated byte count and validate row filter bytes as 0–4. Validate PNG signature, IHDR, chunk lengths/bounds, CRCs, ordering, required IDAT, zlib data, IEND termination and EOF. Reject invalid dimensions, malformed scanlines, unknown critical chunks, truncation, or trailing data.

PNG bytes enter the RTAB payload exactly as stored. Do not re-encode or add compression.

SVG retains the existing UTF-8 XML, well-formedness, and SVG-root validation.

Publish using an atomic no-overwrite operation: create a hard link from the verified staged file to the final path. Hard-link creation fails if the destination already exists. If hard links are unsupported, fail closed; do not fall back to an overwriting rename or copy.

Retry semantics:

Existing final destination with exact expected size and SHA-256: accept as already migrated without writing over it.
Existing destination that differs: stop; preserve it.
Partial/incomplete temp file: never treat as migrated and never publish it.
Ambiguous crash-left staging paths: preserve and report for review; do not wildcard-clean.

9. Exclusive lock, durable journal, and recovery
Use a fixed ignored journal path and a separate exclusive lock file. Create the lock with exclusive-create semantics (open with wx) and hold its handle across recovery, source preparation, validation, publication, stale retirement, and journal cleanup. A second preparation process must fail before recovery or output inspection/mutation while the lock is held. Remove the lock only after closing the handle and verifying its transaction nonce matches this process.

The lock records a transaction ID, nonce, PID, host, and process-start identity for diagnostics. Age alone never establishes staleness. If the lock exists, stop. Do not auto-break it based only on timeout or timestamp. An operator must verify that the recorded process is no longer active and explicitly authorize lock removal; then recovery still validates the journal before any file operation.

Journal records are append-only JSONL with transaction ID, monotonic sequence, operation intent/completion, and record checksum. Before every filesystem mutation, append and flush the complete intent record; after it, append and flush completion. The transaction plan includes:

Every affected destination and whether a prior file existed, with prior hash.
Exact transaction-owned temp and backup paths and expected hashes.
Expected new output hashes and exact output paths.
Old manifest and schema hashes; expected new manifest and schema hashes.
Pending stale outputs, including public/assets/Ships/ships.bin and its prior hash.
Whether the new manifest has been committed.
Recovery runs only after exclusive lock acquisition and before ordinary packaging. An incomplete trailing JSONL line, invalid JSON/checksum, sequence gap, unexpected transaction ID, missing journal phase, or malformed record is ambiguous: preserve all files and backups, report failure, and require review. Never truncate or repair the journal automatically.

Recovery-state table
Recorded state and observed files	Recovery action
Prior manifest/schema/bundles match recorded hashes; new temps match expected hashes; no output replacement occurred	Resume only if the journal records the exact next intent; otherwise stop.
Manifest is still prior (or prior absence); some outputs are new and verified backups match prior hashes	Roll back only journaled paths to the complete prior set. Preserve old outputs and stale Ships bundle.
Manifest is prior but schema or bundles are new, missing, or unknown	Restore only when every required prior backup/hash is present and the prior manifest/schema/bundle set validates after restoration; otherwise preserve all and stop.
Manifest hash equals expected new hash	Do not assume commit from this alone. Validate new manifest, manifest schema, all four bundle paths, each bundle hash/content/records, category membership, and transaction state. If all pass, mark committed and proceed to stale retirement.
New manifest is present but schema/bundle validation fails	Roll back only if the full prior set can be restored and validated from verified backups; otherwise stop and preserve all artifacts.
New set validates; stale nested Ships file matches recorded prior hash and pending retirement intent	Move that exact file to its exact journaled backup path, then verify new set again before deleting the backup.
Any destination, backup, temp, lock nonce, or stale path has unexpected content/hash or contradicts journal state	Stop. Preserve all files; do not guess, overwrite, or delete.
Temp/backup exists without a valid matching journal record	Stop and report it. Never wildcard-delete or infer ownership.
Before retiring stale outputs or deleting any backup, verify the new manifest, manifest schema, all four expected bundle paths, bundle hashes and RTAB contents, and journal transaction state. Old public/assets/Ships/ships.bin remains until this succeeds. If the process stops after publishing schema 1.1 but before manifest 1.1, the prior manifest marks the transaction uncommitted; rollback the schema and any changed bundles only from verified backups. Do not remove the nested Ships bundle.

A journal is a recovery aid, not a claim of multi-file crash atomicity or hardware power-loss durability. If recovery state is not exactly reconcilable, stop and preserve artifacts for manual review.
