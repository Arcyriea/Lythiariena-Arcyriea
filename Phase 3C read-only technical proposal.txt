1. Existing runtime loading architecture
main.ts contains both BootScene and GameScene. Phaser is created with those two scenes at main.ts. Currently, BootScene.preload() queues three loose PNGs, 31 loose game SVGs from the generated manifest, and three separate minimap SVGs. It also creates five dummy textures: ship-core, ship-wing, hardpoint, bullet, and enemy-core. In create(), it registers aliases for the 31 game SVGs, then starts GameScene.

GameScene.create() builds the space and planet backgrounds, player, physics, controls, and minimap. The Game instance is constructed in the GameScene constructor, before GameScene.create() runs. To keep failure before gameplay initialization, I recommend moving that construction into GameScene.create(), which is only reached after BootScene explicitly starts it.

The current planet texture keys are planetMap111, planetMap122, and planetMap692. PlanetBackground passes the selected key to PlanetShader, which supplies it as the Shader Game Object’s sampler texture. Its shader and geometry need no migration changes. See Planet.ts and planets.glsl.

3. Browser-side RTAB parser design
Create a browser-safe parser using Uint8Array, DataView, BigInt, TextDecoder, and crypto.subtle; do not import the Node packager or use Node-only Buffer/crypto APIs.

The format evidence is in package-assets.mjs, which defines a 64-byte header, 28-byte index header, 72-byte records, a 32-byte index digest, versions 0x0100/0x0101, header flags 0x0003, and content codes SVG 0/PNG 1. The existing Node validator at package-assets.mjs checks:

RTAB magic, version, header flags and zeroed reserved bytes.
Little-endian header offsets and sizes, index placement, INDX magic, index flags, record size, and index digest.
Contiguous string-table and payload ranges, valid UTF-8 IDs, unique and sorted IDs, and no unreferenced bytes or trailing payload.
Compression method NONE, zero record flags, nonzero equal stored/original sizes, and payload digest.
Version-specific content rules: v1.0 permits SVG; v1.1 permits SVG and PNG.
The browser reader should retain those checks, applying bounds checks in BigInt before converting offsets to JS numbers. Also verify each full bundle SHA-256 against its manifest bundleSha256, and each payload digest against both the record digest and its sourceSha256.

4. Manifest and inventory validation
Fetch /assets/asset-manifest.json first. Validate its exact shape and manifestSchemaVersion === "1.2" without adding a schema-validation dependency. Validate required asset fields, known content types, aliases, lowercase SHA-256 values, bundle metadata, and no unsupported properties.

Use the existing asset-registry.json as the embedded expected inventory, deriving each bundle from its asset category. Verify each manifest asset’s ID, path, texture key, aliases, type, and derived bundle against it. Cross-check all SVG keys, URLs/paths, and aliases against publicSvgManifest.ts. Validate the three expected planet entries and their keys. Then require exactly 34 assets, with no duplicate IDs or texture keys, and the four expected bundle IDs/counts: components (19, v1.0), ships (10, v1.0), turrets-platforms (2, v1.0), planets (3, v1.1). Require the bundle path for each ID to match the expected /assets/<bundle>.bin path; do not use manifest-provided arbitrary URLs.

Fetch all four bundles only after validating the manifest. Verify exact coverage once across all bundles: every expected ID appears exactly once, and no unexpected or duplicate record appears. Keep the existing approved source fingerprints in the Node validator unchanged.

5. Decode and register images with Phaser 4.2.1
Installed node_modules/phaser/package.json reports 4.2.1. Its actual TextureManager.js documents addImage(key, source) as accepting an HTMLImageElement; the installed phaser.d.ts gives the same type and specifies null on duplicate keys. checkKey() uses exists() and returns false for an existing key. remove() destroys and removes a texture, per TextureManager.js.

Recommended path:

Validate SVG XML/root namespace and PNG decoding from their verified payload bytes.
Create Blob URLs and load each asset into an HTMLImageElement; await image.decode() and require nonzero natural dimensions.
Decode all assets before changing Phaser’s Texture Manager.
Preflight all 34 primary texture keys and three aliases for collisions using textures.exists().
Register each image with textures.addImage(), reusing the same decoded image for its aliases. Fail on a null result; then verify all 37 keys with exists().
On registration failure, remove only keys created by this loading attempt with textures.remove(). Revoke Blob URLs on success and failure.
Do not pass ImageBitmap directly to addImage: Phaser 4.2.1’s public type does not accept it. createImageBitmap is unnecessary for this design; converting it to a canvas would introduce a second conversion path and is not the documented addImage input. The decoded HTMLImageElement path also matches the current alias registration.

6. Startup sequence and error handling
Keep Phaser’s normal BootScene preload for dummy textures and minimap icons. In BootScene create(), call a guarded async startup routine:

Fetch and validate the manifest.
Fetch and validate all four bundles and exact 34-asset coverage.
Decode every bundle payload.
Register all keys and aliases, then verify them.
Start GameScene.
A failed fetch, hash, parse, inventory, decode, collision, or registration step must leave GameScene unstarted. Catch the error in BootScene and show a visible message on the Phaser canvas; do not rely on the loader’s queued-file failure UI. Defer Game construction to GameScene.create() so a failure also prevents creation of the gameplay engine instance.

Separate parser tests from Phaser/browser tests.

Confirm network requests for migrated game SVGs and planet PNGs do not occur; the three minimap SVG requests remain. Exercise a missing bundle and corrupted payload to confirm the BootScene error is visible and gameplay stays inactive.

8. Risks and unresolved details
crypto.subtle requires a secure context in deployed browsers; localhost is treated as secure, but deployment should use HTTPS. Fail visibly if SHA-256 verification is unavailable.
TextureManager.addImage registers a texture synchronously after the image is decoded, but GPU upload may happen lazily during rendering. Verify the planet shader in a real WebGL browser.
Blob image decoding may be restricted by a future Content Security Policy. If CSP is introduced, its img-src must allow blob:.
Hashes detect inconsistencies relative to the fetched manifest; they do not authenticate a manifest that an attacker can replace together with its bundles. Serve them over HTTPS and treat this loader as integrity validation, not signature verification.
The Game constructor currently runs while Phaser constructs GameScene. Deferring it to create() is a narrowly scoped lifecycle change to satisfy fail-closed startup.
